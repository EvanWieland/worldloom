## Fit with our pipeline

- Loop closure is Wan 2.2 Fun VACE, which works on **any** source video (the VACE joiner community uses it on LTX and stock footage). So the chain model can change without losing the closure.
- Sliding-window chaining, colour correction and 121 f windows are WanGP features that exist for Hunyuan and LTX too, but the proven settings are Wan-specific.
- Motion-prompting rules (`motion-prompting.md`) were learned on Wan; expect to re-tune NAG/wording per model.

## How others lock LTX's camera (desk research, 2026-09-24)

- **Prompt vocabulary** ([LTX-2.3 prompt guide](https://ltx.io/blog/ltx-2-3-prompt-guide), [LTX-2 guide](https://crepal.ai/blog/aivideo/blog-ltx-2-prompting-guide/)): "static frame" / "locked-off static camera" are the documented terms; unspecified camera → the model drifts by default; avoid words like pan/zoom/parallax anywhere in the prompt. We already do this; it did not stop the push-in or tilt here.
- **Cinemagraph LoRA** ([HF](https://huggingface.co/Lightricks/LTX-2.3-22b-LoRA-Cinemagraph)): tried; strength 2.5–3.0 kills the zoom, leaves a ~38 px/5 s vertical tilt.
- **Camera-Control-Static LoRA** ([HF](https://huggingface.co/Lightricks/LTX-2-19b-LoRA-Camera-Control-Static)): the purpose-built fix, but trained for LTX-2 **19B** only; no 2.3/2.5 version (an open HF discussion asks for one).
- **IC-LoRA Union Control, depth mode** ([HF](https://huggingface.co/Lightricks/LTX-2.3-22b-IC-LoRA-Union-Control), [tutorial](https://ltxworkflow.com/resources/tutorials/ic-lora-ltx-2-3-complete-guide)): Lightricks' own guidance is "Depth to control camera movement". A control video made of the keyframe's depth map, repeated for every frame, tells the model the camera never moves. **Native in WanGP** (`union_control_lora` = `ltx-2.3-22b-ic-lora-union-control-ref0.5.safetensors`, control modes P/D/E, adjustable control strength). Risk: may also damp motion of elements whose depth changes (falling water, mist) — tune control strength.
- **IC-LoRA Cameraman** ([HF](https://huggingface.co/Cseti/LTX2.3-22B_IC-LoRA-Cameraman_v1), Apache 2.0): transfers camera motion from a reference video; a static reference could in principle force zero motion, but that use is undocumented.
- **Post-stabilisation** ([ffmpeg vid.stab](https://ffmpeg-cookbook.com/en/articles/video-stabilization/)): the standard fix for AI-video drift/jitter; tripod mode locks to a reference frame. Deterministic, whole-frame (not a mask), but must crop/zoom in by the drift (~8 % for 38 px at 480p) and cannot undo parallax.

**Recommendation:** test the Union IC-LoRA with a static depth control video from the keyframe (strength 1.0 and 0.5), measured with the ORB camera track and judged by eye. Fallbacks in order: vid.stab tripod mode on the Cinemagraph clip; Cameraman IC-LoRA with a static reference.
- **Depth-lock test (LTX-2.5 distilled + Union Control IC-LoRA, WanGP `video_prompt_type: "DVG"`, control video = the keyframe held for 121 f, WanGP's depth preprocessing), ORB camera track:** control strength 1.0 → **0.6 px / 0.08 % zoom**; 0.5 → **0.8 px / 0.18 %**; Wan 0.3 px / 0.04 %; Cinemagraph 3.0 was 38 px. Scene motion (median flow) 0.15 px/f vs Wan 0.24 — somewhat damped but alive. 4–5 min per 5 s clip. **First method that locks LTX's camera by measurement.** Comparison `experiments/model_ab/COMPARE_ltx_depthlock.mp4`; verdict pending.
